## 1. Что это

Собственная площадка поиска госзакупок (44/223-ФЗ) — аналог Тендерплана/Контура, но
**независимая**: свой сбор данных напрямую с площадок. Поиск по ключевым словам, лента
закупок со всех источников, фильтры, скачивание документов, личные кабинеты компаний.
Дифференциатор сверху — **сверка своего ТЗ с ТЗ закупки** (надстройка).

**Разворот (было→стало):** проект начинался как «SpecMatch» — надстройка на API
Тендерплана (подбор закупок под товар по характеристикам ТЗ). Ушли от зависимости от
конкурента к своей площадке со своим сбором данных.

### Аналитика (новое, 2026-07-28)
- [x] **Ценовой ориентир по категориям**: реестр контрактов ЕИС (`epz/contract/search/results.html`) —
  отдельная база от активных закупок, содержит реальную цену заключённых контрактов. НЕ глушится
  антиботом для `searchString` (в отличие от поиска активных закупок) — собирается обычным curl.
  `tools/build_analytics.js` тянет ~100 контрактов по каждой из тех же ~30 тем, что и поиск, считает
  медиану/среднее/диапазон → `site/data/analytics.json`. На карточке закупки — сопоставление темы той
  же stem-логикой, что и в поиске, + % отклонения текущей НМЦК от медианы по рынку.
- [x] **История заказчика**: та же выборка контрактов, группировка по нормализованному имени
  заказчика (ИНН в реестре контрактов не показан даже в списке — поэтому по имени, не по ИНН) →
  число контрактов, средний чек, диапазон дат.
- [ ] **Уровень конкуренции** — НЕ реализовано, разведано и сознательно отложено (2026-07-28).
  Нашли вкладку `.../notice/<тип>/view/supplier-results.html?regNumber=...` («Результаты определения
  поставщика») на карточке КАЖДОЙ закупки — но она показывает **только строку победителя**
  («1 — Победитель»), не полный список заявок, даже для реально конкурентных закупок (проверено на
  нескольких примерах). Число участников надёжно читается текстом только в вырожденном случае «по
  окончании срока подачи заявок подана только одна заявка» (= 0 конкурентов) — для настоящей
  конкуренции этих цифр тут нет, они в отдельном PDF/DOC протоколе рассмотрения заявок (другая,
  большая задача на разбор документов, не структурированный HTML). Технически: эта вкладка не
  открывается голым curl даже с `-L` (честный 404, нужен Chromium с переходом+кликом — 2 захода
  браузером на закупку); чтобы набрать выборку сравнимую с ценовой (~100×30=3000 закупок) — это
  часы работы headless-браузера по источнику, кардинально больше нагрузки, чем всё остальное. Решили
  не показывать метрику вообще, а не показывать искажённую (тольк «0 конкурентов» ловилось бы
  надёжно, реальная конкуренция — нет). В UI явно написано, что не считается.
- Аналитика пересобирается не чаще раза в сутки (`tools/refresh.sh`, `LK_ANALYTICS_MAX_AGE_HOURS`) —
  история контрактов не меняется от часа к часу, как активные закупки.

## 3. ⭐ Открытое прямо сейчас

Всё из этого раздела на 2026-07-28 закрыто:

- ~~Антибот источника глушит поиск по словам для «голых» HTTP-клиентов~~ — **решено**:
  curl с этой машины получал «0 записей» на ЛЮБОЙ поисковый запрос (не IP-бан, а разбор

  нормально. Прицельный поиск по темам (`collectEis`) теперь идёт через Playwright вместо
  curl (общий список — по-прежнему curl, там не мешает), плюс пауза 400-800мс между темами
  и честные Accept/Accept-Language заголовки. **Не обходить проксями/спуфингом** — это уже
  не инженерия, а обход защиты чужого сайта.
- ~~Git-рост снапшота~~ — **решено**: снапшот больше не коммитится в git, доставляется
  на VPS напрямую по `scp` (`tools/refresh.sh`), атомарно (временный файл + `mv` на сервере).
- ~~2FA~~ — **решено**: TOTP (Google Authenticator/Authy/Яндекс Ключ), опционально на
  каждого пользователя. Настройка/QR/подтверждение/отключение — в `account.html`; второй
  шаг входа — в `login.html`. Свои rate-limit (8 попыток/5мин) и краткоживущий (5 мин)
  токен на время между паролем и кодом — не расходуется на опечатке, только на успехе.
  Проверено сквозным тестом (регистрация → включить → выйти → войти с кодом → неверный код
  отклонён → верный пускает → отключить → вход снова без кода).

## 5. Зафиксированные решения

- **Источник — свой сбор напрямую** (не агрегатор). Портал поставщиков (чистый JSON) и ЕИС
  (HTML) вскрыты и работают анонимно.
- **Сбор — на машине пользователя**, т.к. гос-сайты блокируют IP дата-центров (VPS не видит источники).
- **Прод — статический снапшот на VPS** для ленты закупок (быстро, дёшево); **живой бэкенд
  для личных кабинетов** (аккаунты/сотрудники/подписка/сверка ТЗ — это не требует доступа
  к гос-источникам, поэтому работает на текущем VPS без ограничений).
- **Прицельный поиск по темам ЕИС — через headless-браузер (Playwright), не curl** — источник
  различает голые HTTP-клиенты и настоящие браузеры именно для поисковых запросов.
- **Скачивание файлов — прямыми ссылками** из браузера пользователя (CORS не мешает навигации).
- **Nexara — отдельный проект**, его заменили на этом VPS (бэкап снят).
